# Groqによる会議要約の接続準備

OpenAI/Lunaに加えてGroqを要約先として選択できます。途中要約と最終要約・TODOを共通の形式で検証し、既存の保存・履歴表示・HTML→PDF変換へ渡します。要約先はサーバー単位で1つ選びます。文字起こし・整文のproviderは変更しません。

## 設定

サーバー専用の .env の同名設定を編集します。キーの値をチャット・GitHubへ載せず、VITE_ へ入れないでください。

```dotenv
SUMMARY_ENABLED=true
SUMMARY_PROVIDER=groq
GROQ_SUMMARY_API_KEY=
GROQ_SUMMARY_MODEL=openai/gpt-oss-20b
GROQ_SUMMARY_MAX_INPUT_BYTES=12000
GROQ_SUMMARY_MAX_OUTPUT_TOKENS=2048
SUMMARY_MAX_REQUESTS_PER_MEETING=5
SUMMARY_MEETING_BUDGET_USD=
SUMMARY_MONTHLY_BUDGET_USD=
GROQ_SUMMARY_PRICING_JSON=
```

GROQ_SUMMARY_API_KEY に、利用を許可したGroqキーをローカルで設定してください。同じGroqアカウントの既存キーを設定することもできますが、文字起こし・整文のキーを自動流用しません。OpenAIのキー・モデル設定も書き換えません。

金額上限を空欄にする例は、無料プランでの試験を意図しています。課金プランなら、GROQ_SUMMARY_PRICING_JSON に選択モデルの確認済み単価を設定したうえで金額上限を設定してください。金額上限があるのに価格が未登録の場合は送信せずに失敗します。無料枠だからという理由で料金を自動的にゼロとは扱いません。アプリの予算判定は厳密な請求上限ではありません。

起動プロセスを再起動し、会議準備を開き直します。「ボタンで途中要約を作る」「会議終了後に最終要約とTODOを作る」を必要に応じて選び、Groqへ文字起こしと要約を送る説明を確認して同意します。準備後に送信先が変わった場合は送信を拒否します。会議画面にはGroq要約と表示します。

Lunaへ戻すには SUMMARY_PROVIDER=openai に戻し、元のOpenAI用キー・モデル・価格・予算設定を使って再起動し、新しい会議の準備画面で同意を確認します。失敗時に別のサービスへ自動送信するフォールバックはありません。

## 対応範囲と無料枠

- 対応モデルは openai/gpt-oss-20b と openai/gpt-oss-120b。既定は20bです。
- JSON Schemaのstrictモードを使用し、形式だけでなく期待versionと根拠文IDもアプリ側で検証します。
- 途中要約では、新しい確定文と以前の要約を送ります。最終要約では、その会議の確定文全体と途中要約を送ります。音声・暫定文・別の会議の本文は要約経路へ送りません。
- 入力JSON（確定文・以前の要約・ID等を含む）が既定12,000 UTF-8バイトを超えると、送信前に拒否します。文字数やトークン数とは異なり、無料枠に必ず収まる保証ではありません。
- 超過時に本文を切り捨てたり、最後の部分だけ要約したりしません。文字起こし履歴は維持します。長い会議の自動分割・段階要約は今回未実装です。1〜1.5時間の会議全文を無料枠で扱える状態の完成を意味しません。
- 429は固定メッセージで通知します。自動再試行・他providerへの切り替えはしません。時間をおいて利用者が再試行します。
- 同時処理はprovider内で1件、応答サイズは既定256KiB、待機時間は SUMMARY_TIMEOUT_MS（既定60秒）、出力上限は既定2,048トークンです。打ち切られた出力・拒否・不正な根拠は成功扱いにしません。
- APIが返した有効なusageを本文と分けて保存し、要約呼び出し回数・トークン数を表示します。APIがusageを返さない通信失敗等の利用量は把握できません。回数制限は記録できたusageを基準にするため、提供元側の上限と併用してください。
- Groqの無料枠は組織で共有されます。整文に同じモデルを使う場合は処理量も競合し得ます。最新の上限はGroq ConsoleのLimitsで確認してください。

APIの保存・学習利用条件はGroq側の設定・規約に従います。未対応の store パラメーターに依存して保存されないと約束しません。

履歴のレイアウト・IndexedDBのDBバージョン・MeetingRecordのschemaVersionは変更しません。既存provider欄でgroqを受理するよう拡張しています。Groqで保存した履歴を読むときは、この変更を含む版を使ってください。

## 比較試験の進め方

通常の自動テストはFake HTTPだけで、実キーを読み込んだり外部LLMを呼んだりしません。

実API試験を行う際は、利用者が送信を許可した合成の短い会議で実施してください。

1. 同じ発言でLunaとGroqを別の試験として実行します。最初は途中要約OFF・最終要約ONです。
2. 「決定」と「提案」、否定・条件、金額・日付を意図的に混ぜます。
3. 担当者・期限が不明なTODOは未設定になり、発言にない決定が追加されないか確認します。
4. 成功した要約が履歴へ保存され、再読み込み後にGroqの表示とTODOが残るか確認します。
5. PDFの内容と、Groqの利用量・待ち時間を確認します。
6. その後に途中要約をONにし、前回要約と新しい発言の統合を確認します。

意味の正確さ、1〜1.5時間の会議、利用者のアカウントでのAPI対応・無料枠、実マイクと実ブラウザーは未確認です。
